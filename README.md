# OCL Server Prepare

Интерактивный установщик для первоначальной настройки сервера на Ubuntu 24.04 LTS.

Проект развивается небольшими шагами. Текущая версия проверяет запуск от root и
поддерживаемую ОС, затем предлагает сменить пароль root, создаёт пользователя и
выдаёт ему права sudo без пароля, предлагает изменить имя сервера и настраивает
публичные SSH-ключи пользователя.
Остальные шаги настройки и обновление пока не реализованы.

## Установка и обновление одной командой

Подключитесь к серверу под root. Если используете пользователя с правами sudo,
сначала выполните:

```bash
sudo -i
```

Для загрузки нужны `curl` и `tar`. Единая команда запуска установщика:

```bash
ocl_installer=$(curl -fsSL https://raw.githubusercontent.com/lenyldes/OCL-Server-Prepare/main/install.sh) && bash -c "$ocl_installer"
```

Команда полностью загружает скрипт и запускает его через Bash только при успешной
загрузке. Скрипт скачивает архив проекта и запускает все доступные шаги настройки.
Ввод с терминала остаётся доступен для вопросов установщика. Временные файлы
удаляются после завершения.

Команда станет доступна после публикации изменений в ветке `main` на GitHub.

## Смена пароля root

На вопрос `Сменить пароль root? [y/N]` введите `y` для смены пароля или нажмите
Enter для пропуска. При повторном запуске установщик снова задаёт этот вопрос.

Для генерации используется системная команда `openssl`. Установщик создаёт
случайный пароль длиной 30 символов и выводит его после успешной смены. Сохраните
пароль: установщик не записывает его в открытом виде в файлы или логи.

## Создание пользователя

Введите имя пользователя или нажмите Enter для выбора `lenyldes`. Установщик
запускает интерактивный `adduser`, который создаёт домашний каталог и группу
пользователя и запрашивает пароль с повторным вводом. Вопросы про полное имя,
кабинет и телефоны пропускаются. Пароль не попадает в переменные установщика.

Если пользователь уже существует, его пароль сохраняется. Если пароль не задан
или заблокирован, установщик остановится с подсказкой выполнить `passwd` для
этого пользователя и повторить запуск.

## Права sudo

После создания или проверки пользователя установщик автоматически добавляет его
в группу `sudo`, сохраняя членство в остальных группах. Повторный запуск безопасен.
Для применения новых прав пользователю нужно выйти из системы и войти заново.

Затем установщик создаёт `/etc/sudoers.d/<имя пользователя>` с правилом
`<имя пользователя> ALL=(ALL) NOPASSWD: ALL`, владельцем `root:root` и правами
`0440`. Перед применением правило проверяется через `visudo`. Пароль при
выполнении любых команд через sudo больше не запрашивается.

При повторном запуске такое же правило сохраняется без дублирования. Если файл
уже содержит другие настройки, установщик остановится, не изменяя его.

## Имя сервера

Установщик показывает текущее имя сервера и предлагает новое. Нажмите Enter или
введите текущее имя для пропуска. Новое короткое имя должно содержать от 1 до 63
строчных латинских букв, цифр или дефисов, без дефиса в начале и конце.
При неверном вводе вопрос повторяется.

Имя применяется через `hostnamectl set-hostname` и заменяется в строке
`127.0.1.1` файла `/etc/hosts`. Прочие строки, дополнительные алиасы и комментарий
сохраняются. Если строки нет, она добавляется. При ошибке установщик
останавливается; если обновление `/etc/hosts` не удалось, он пытается вернуть
прежнее имя сервера и сообщает об ошибке отката, если тот также не удался.

## SSH-ключи

После настройки имени сервера установщик показывает SHA256-отпечаток публичного
ключа по умолчанию из `keys/default.pub`. На первом вопросе нажмите Enter, чтобы
добавить этот ключ, или введите собственный публичный OpenSSH-ключ целиком одной
строкой. Затем можно добавлять другие ключи по одному; пустая строка завершает
ввод. При ошибке проверки через `ssh-keygen` вопрос повторяется.

Ключи сохраняются в `.ssh/authorized_keys` настоящего домашнего каталога выбранного
пользователя. Существующие строки и комментарии сохраняются; повторный ввод того
же ключа с другим комментарием не создаёт дубль. Ограничения существующего ключа
в options также сохраняются. Новый ввод принимает обычные ключи без options.
Для завершения нужен хотя бы один действительный ключ в итоговом файле.
Каталог `.ssh` получает права `0700`, файл `authorized_keys` — `0600`; владельцем
становится выбранный пользователь с его основной группой.

В репозитории хранится только публичный ключ по умолчанию. Приватный ключ
необходим для входа и должен оставаться у его владельца.

## Локальный запуск

Из каталога проекта на сервере:

```bash
bash setup.sh
```

## Структура проекта

```text
install.sh               # Загрузка проекта и запуск настройки
setup.sh                 # Проверки и порядок выполнения шагов
steps/root-password.sh   # Смена пароля root
steps/user.sh            # Создание пользователя
steps/sudo.sh            # Выдача прав sudo
steps/sudo-nopasswd.sh   # Настройка sudo без пароля
steps/hostname.sh        # Настройка имени сервера
steps/ssh-keys.sh        # Настройка SSH-ключей пользователя
keys/default.pub         # Публичный SSH-ключ по умолчанию
```
