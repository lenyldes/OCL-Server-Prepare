# OCL Server Prepare

Установщик для первоначальной настройки сервера на Ubuntu 24.04 LTS.

Проект развивается небольшими шагами. Текущая версия проверяет запуск от root и
поддерживаемую ОС, затем предлагает сменить пароль root, создаёт пользователя и
выдаёт ему права sudo без пароля, предлагает изменить имя сервера и настраивает
публичные SSH-ключи пользователя, SSH-сервер, фаервол UFW и Zsh с Oh My Zsh.
Обновление системы пока не реализовано.

## Установка и обновление одной командой

Подключитесь к серверу под root. Если используете пользователя с правами sudo,
сначала выполните:

```bash
sudo -i
```

Для загрузки нужны `curl` и `tar`. Единая команда запуска установщика:

```bash
ocl_installer=$(curl -fsSL https://raw.githubusercontent.com/lenyldes/OCL-Server-Prepare/main/install.sh) && bash -c "$ocl_installer"
```

Команда полностью загружает скрипт и запускает его через Bash только при успешной
загрузке. Скрипт скачивает архив проекта и запускает все доступные шаги настройки.
Ввод с терминала остаётся доступен для вопросов установщика. Временные файлы
удаляются после завершения.

Команда станет доступна после публикации изменений в ветке `main` на GitHub.

## Режим установки

После проверки запуска от root и версии ОС первый вопрос —
`Установить со значениями по умолчанию? [y/N]`. Ответ `y` запускает настройку
без дальнейших вопросов: новый пароль root генерируется при каждом запуске,
пользователь — `lenyldes`, имя сервера сохраняется, добавляется ключ из
`keys/default.pub`, порт SSH — `18233`. Sudo, UFW и Zsh настраиваются автоматически.
Ответ `n` или Enter сохраняет ручной выбор на следующих шагах.

В конце установщик показывает статус и сгенерированные этим запуском пароли.
Сводка появляется и при ошибке последующего шага: уже установленные пароли
остаются действующими. Сохраните их; установщик держит пароли только в памяти,
не записывая их в файлы и не передавая через переменные окружения.

## Смена пароля root

В ручном режиме на вопрос `Сменить пароль root? [y/N]` введите `y` для смены
пароля или нажмите Enter для пропуска. При повторном запуске установщик снова
задаёт этот вопрос. В автоматическом режиме пароль root меняется каждый раз.

Для генерации используется системная команда `openssl`. Установщик создаёт
случайный пароль длиной 30 символов и выводит его в итоговой сводке после успешной
смены.

## Создание пользователя

В ручном режиме введите имя пользователя или нажмите Enter для выбора `lenyldes`.
Установщик запускает интерактивный `adduser`, который создаёт домашний каталог
и группу пользователя и запрашивает пароль с повторным вводом. Вопросы про
полное имя, кабинет и телефоны пропускаются. Введённый пароль не попадает
в переменные установщика.

В автоматическом режиме новый пользователь `lenyldes` создаётся без вопросов.
Ему задаётся случайный пароль длиной 30 символов, который выводится в итоговой
сводке.

Если пользователь уже существует, его пароль сохраняется. Если пароль не задан
или заблокирован, установщик остановится с подсказкой выполнить `passwd` для
этого пользователя и повторить запуск. Это правило действует в обоих режимах;
сохранённый пароль установщику неизвестен и в сводке не выводится.

## Права sudo

После создания или проверки пользователя установщик автоматически добавляет его
в группу `sudo`, сохраняя членство в остальных группах. Повторный запуск безопасен.
Для применения новых прав пользователю нужно выйти из системы и войти заново.

Затем установщик создаёт `/etc/sudoers.d/<имя пользователя>` с правилом
`<имя пользователя> ALL=(ALL) NOPASSWD: ALL`, владельцем `root:root` и правами
`0440`. Перед применением правило проверяется через `visudo`. Пароль при
выполнении любых команд через sudo больше не запрашивается.

При повторном запуске такое же правило сохраняется без дублирования. Если файл
уже содержит другие настройки, установщик остановится, не изменяя его.

## Имя сервера

Установщик показывает текущее имя сервера и предлагает новое. Нажмите Enter или
введите текущее имя для пропуска. Новое короткое имя должно содержать от 1 до 63
строчных латинских букв, цифр или дефисов, без дефиса в начале и конце.
При неверном вводе вопрос повторяется.

Имя применяется через `hostnamectl set-hostname` и заменяется в строке
`127.0.1.1` файла `/etc/hosts`. Прочие строки, дополнительные алиасы и комментарий
сохраняются. Если строки нет, она добавляется. При ошибке установщик
останавливается; если обновление `/etc/hosts` не удалось, он пытается вернуть
прежнее имя сервера и сообщает об ошибке отката, если тот также не удался.

## SSH-ключи

После настройки имени сервера установщик показывает SHA256-отпечаток публичного
ключа по умолчанию из `keys/default.pub`. На первом вопросе нажмите Enter, чтобы
добавить этот ключ, или введите собственный публичный OpenSSH-ключ целиком одной
строкой. Затем можно добавлять другие ключи по одному; пустая строка завершает
ввод. При ошибке проверки через `ssh-keygen` вопрос повторяется.

Ключи сохраняются в `.ssh/authorized_keys` настоящего домашнего каталога выбранного
пользователя. Существующие строки и комментарии сохраняются; повторный ввод того
же ключа с другим комментарием не создаёт дубль. Ограничения существующего ключа
в options также сохраняются. Новый ввод принимает обычные ключи без options.
Для завершения нужен хотя бы один действительный ключ в итоговом файле.
Каталог `.ssh` получает права `0700`, файл `authorized_keys` — `0600`; владельцем
становится выбранный пользователь с его основной группой.

В репозитории хранится только публичный ключ по умолчанию. Приватный ключ
необходим для входа и должен оставаться у его владельца.

## SSH-сервер

После установки ключей введите порт SSH или нажмите Enter для выбора `18233`.
Допускаются целые числа от 1 до 65535; при неверном вводе вопрос повторяется.
Установщик целиком заменяет `/etc/ssh/sshd_config` конфигурацией из
`templates/sshd_config`, подставляя выбранный порт. Вход root, пароли,
интерактивная аутентификация и X11 отключаются; вход по ключам, PAM и SFTP
сохраняются. Шаблон не подключает `/etc/ssh/sshd_config.d/`: настройки cloud-init
и другие фрагменты из этого каталога перестают влиять на SSH.

Перед заменой кандидат проверяется через `sshd -t -f`, а исходный файл сохраняется
в уникальный `/etc/ssh/sshd_config.ocl-backup.*`; установщик выводит полный путь.
Файл заменяется атомарно, с владельцем `root:root` и правами `0644`.
Если содержимое уже совпадает, новая резервная копия не создаётся и SSH не
перезапускается.

Режим запуска SSH сохраняется. При socket activation Ubuntu установщик выполняет
`systemctl daemon-reload` и перезапускает `ssh.socket` вместе с `ssh.service`,
проверяя активность и выбранный порт сокета. При запуске без сокета перезапускается
только `ssh.service`. Пользовательские переопределения systemd не изменяются;
если они мешают применить порт, установщик сообщает об ошибке. При ошибке после
замены он пытается восстановить прежний файл и перезапустить SSH; если откат
не удался, выводит путь к резервной копии для ручного восстановления.

Сохраните текущее подключение и проверьте новый вход по ключу:
`ssh -p <порт> <пользователь>@<сервер>`. На серверах со штатным `KillMode=process`
перезапуск сохраняет уже открытые SSH-сессии. Фаервол и сетевые перенаправления
этот шаг не изменяет; выбранный порт должен быть доступен извне.

## Фаервол UFW

После настройки SSH установщик, если UFW отсутствует, обновляет список пакетов
через `apt-get update` и устанавливает UFW через `apt-get install -y ufw`,
затем читает действующий порт из `sshd -T`. Конфигурация должна
содержать единственный SSH-порт. Шаг рассчитан на первоначальную настройку чистого
VPS без существующих правил фаервола.

Сначала добавляется `ufw limit <порт>/tcp comment 'SSH limit'`, затем задаются
политики `deny incoming` и `allow outgoing` и включается UFW. Так доступ к SSH
разрешается с ограничением частоты подключений до включения фаервола. Повторный
запуск с тем же портом не дублирует правило. При ошибке установщик останавливается.
Настройки облачного фаервола и сетевые перенаправления не изменяются.

## Zsh и Oh My Zsh

После UFW установщик настраивает оболочку только выбранного пользователя.
Отсутствующие пакеты `zsh`, `git` и `fzf` устанавливаются через `apt-get update`
и `apt-get install -y`; уже установленные пакеты не обновляются.

Oh My Zsh устанавливается официальным инсталлятором из ветки `master`
репозитория [ohmyzsh/ohmyzsh](https://github.com/ohmyzsh/ohmyzsh).
Репозитории загружаются от имени выбранного пользователя в его настоящий
домашний каталог. Инсталлятор работает без вопросов, не запускает Zsh
и не меняет оболочку; его временный `.zshrc` не затрагивает настройки пользователя.

В `.zshrc` включаются тема `lenyldes` и плагины в следующем порядке:
`colored-man-pages`, `docker`, `docker-compose`, `kubectl`, `helm`, `terraform`,
`fzf`, `zsh-completions`, `zsh-autosuggestions`, `zsh-syntax-highlighting`.
Последний плагин остаётся последним. Первые семь входят в Oh My Zsh;
остальные загружаются из одноимённых репозиториев
[zsh-users](https://github.com/zsh-users).
Каталог дополнений `zsh-completions/src` добавляется в `fpath` до загрузки
Oh My Zsh, чтобы штатный `compinit` сразу зарегистрировал команды.
Плагин остаётся в списке; повторное добавление пути не создаёт дубликат.
Docker, Kubernetes, Helm, Terraform и другие программы для этих плагинов
не устанавливаются. Плагин `fzf` подключает дополнения и сочетания клавиш
из установленного системного пакета.

Шаблоны `.zshrc` и темы целиком заменяют соответствующие файлы пользователя.
При реальном изменении существующий файл сохраняется рядом в уникальную
копию с суффиксом `.ocl-backup.*`; путь выводится в терминал.
Настройки принадлежат выбранному пользователю и его основной группе,
права файлов — `0644`. При повторном запуске совпадающие настройки
не создают резервных копий, а существующие репозитории не скачиваются
и не обновляются. Если каталог занимает другой репозиторий,
неподходящий файл или символическая ссылка, установщик останавливается
с объяснением и сохраняет данные.

Оболочка пользователя меняется на Zsh через `chsh` только после успешной
установки всех компонентов и настроек. Для применения войдите на сервер заново.
Настройки root не изменяются.

## Локальный запуск

Из каталога проекта на сервере:

```bash
bash setup.sh
```

## Структура проекта

```text
install.sh               # Загрузка проекта и запуск настройки
setup.sh                 # Проверки и порядок выполнения шагов
steps/root-password.sh   # Смена пароля root
steps/user.sh            # Создание пользователя
steps/sudo.sh            # Выдача прав sudo
steps/sudo-nopasswd.sh   # Настройка sudo без пароля
steps/hostname.sh        # Настройка имени сервера
steps/ssh-keys.sh        # Настройка SSH-ключей пользователя
steps/sshd.sh            # Настройка SSH-сервера
steps/ufw.sh             # Настройка фаервола UFW
steps/zsh.sh             # Настройка Zsh и Oh My Zsh выбранного пользователя
keys/default.pub         # Публичный SSH-ключ по умолчанию
templates/sshd_config    # Конфигурация SSH-сервера
templates/zshrc          # Конфигурация Zsh пользователя
templates/lenyldes.zsh-theme # Тема Oh My Zsh
```
