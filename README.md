# OCL Server Prepare

![Ubuntu](https://img.shields.io/badge/Ubuntu-24.04_LTS-E95420?style=flat&logo=ubuntu&logoColor=white)
![Bash](https://img.shields.io/badge/Bash-скрипты-4EAA25?style=flat&logo=gnubash&logoColor=white)

## Что это такое?

Это набор Bash‑скриптов, чтобы быстро подготовить сервер на Ubuntu 24.04 LTS. 
За один запуск происходит создание пользователя, выдача sudo‑прав, настройка доступа по SSH, межсетевого экрана и удобной оболочки Zsh.

## Зачем нужен этот проект

На каждом новом сервере приходится делать одно и то же: завести пользователя, добавить SSH‑ключи, настроить sudo, закрыть лишние подключения и привести терминал к привычному виду.

Мне надоело повторять эти шаги вручную, поэтому я собрал их в один установщик. Теперь можно либо быстро поднять сервер с моими настройками, либо пройти те же шаги с подсказками и выбрать свои значения.

## Быстрый запуск

Нужен сервер с **Ubuntu 24.04 LTS**, доступом в интернет и установленными `curl`, `tar`, `openssl`, `sudo` и OpenSSH Server. Запускайте установщик в интерактивном терминале — например, через SSH.

**1. Перейдите в root**, если подключились под обычным пользователем:

```bash
sudo -i
```

**2. Запустите установщик:**

```bash
ocl_installer=$(curl -fsSL https://raw.githubusercontent.com/lenyldes/OCL-Server-Prepare/main/install.sh) && bash -c "$ocl_installer"
```

Команда загружает скрипт и запускает его через Bash только при успешной загрузке. \
Скрипт скачает архив проекта из ветки `main` и выполнит все доступные шаги настройки. Ввод с терминала остаётся доступным для ответов на вопросы установщика. Временные файлы удаляются после завершения.

При запуске установщик предложит применить настройки со значениями по умолчанию:

- **`y`** — выполнит настройку без дополнительных вопросов: сменит пароль root, создаст пользователя `lenyldes`, добавит ключ из [keys/default.pub](keys/default.pub) и выставит порт SSH `18233`. Текущее имя сервера сохранится.
- **`n` или Enter** — предложит выбрать имя пользователя, SSH‑ключи и порт, при необходимости сменить пароль root и имя сервера. Остальные шаги выполнятся автоматически.

Если у вас нет приватного ключа, который соответствует `keys/default.pub`, выберите **`n`** и вставьте свой публичный SSH‑ключ. Вход по паролю и вход root по SSH будут отключены в обоих режимах; пользователь получит sudo без пароля.

**3. Сохраните результат и проверьте подключение.**

В конце установщик покажет итог и сгенерированные пароли, если они менялись. Обязательно сохраните их. Для уже существующего пользователя пароль останется прежним.

Не закрывая текущую SSH‑сессию, откройте вторую и подключитесь с приватным ключом, который соответствует добавленному публичному:

```bash
ssh -i ~/.ssh/id_ed25519 -p 18233 lenyldes@SERVER_IP
```

Замените `SERVER_IP` на адрес сервера, а путь к ключу, имя пользователя и порт — на выбранные при настройке. Если у провайдера есть отдельный сетевой экран, заранее разрешите в нём выбранный TCP‑порт SSH.

### Запуск из клонированного репозитория

Если хотите сначала изучить скрипты или поменять шаблоны, скачайте проект через Git и запустите его от root:

```bash
git clone https://github.com/lenyldes/OCL-Server-Prepare.git
cd OCL-Server-Prepare
bash setup.sh
```

Для этого варианта дополнительно нужен `git`. Настройка и выбор режима такие же, как при быстром запуске.

## Что выполняет установщик

`install.sh` только скачивает и распаковывает проект во временный каталог, запускает `setup.sh` и удаляет скачанные файлы после завершения. Сам `setup.sh` проверяет права root и версию Ubuntu, затем последовательно выполняет шаги ниже.

Скрипты в `steps/` подключаются установщиком и используют общие настройки. Для обычного запуска достаточно `install.sh` или `setup.sh`.

### 1. Пароль root — `steps/root-password.sh`

Скрипт генерирует случайный пароль длиной 30 символов и устанавливает его для root. В ручном режиме сначала спрашивает, нужна ли смена пароля; по умолчанию этот шаг пропускается. В автоматическом режиме пароль меняется всегда.

Новый пароль выводится в итогах настройки — в том числе если на следующих шагах возникнут ошибки.

### 2. Пользователь — `steps/user.sh`

Скрипт создаёт отдельного пользователя с домашним каталогом. Имя по умолчанию — `lenyldes`; в ручном режиме можно указать другое имя и задать пароль через `adduser`. В автоматическом режиме пароль генерируется и выводится в итогах.

Если пользователь уже существует, установщик использует его и сохраняет пароль. При отсутствии или блокировке пароля настройка останавливается с подсказкой задать его через `passwd`.

### 3. Права sudo — `steps/sudo.sh`

Скрипт добавляет выбранного пользователя в группу `sudo`. Новое членство в группе применится после повторного входа в систему.

### 4. Sudo без пароля — `steps/sudo-nopasswd.sh`

Скрипт разрешает пользователю выполнять любые команды через sudo без ввода пароля. Правило сохраняется в `/etc/sudoers.d/ИМЯ_ПОЛЬЗОВАТЕЛЯ` после проверки через `visudo`.

Если такой файл уже существует с другим содержимым, установщик остановится, сохранив прежние настройки.

### 5. Имя сервера — `steps/hostname.sh`

В ручном режиме скрипт предлагает изменить hostname. Нажатие Enter сохраняет текущее имя; в автоматическом режиме оно также не меняется.

При смене имени скрипт обновляет hostname через `hostnamectl` и запись `127.0.1.1` в `/etc/hosts`.

### 6. SSH‑ключи — `steps/ssh-keys.sh`

Скрипт добавляет публичные ключи в `~/.ssh/authorized_keys` выбранного пользователя. В ручном режиме принимает ключ целиком одной строкой, затем предлагает добавить дополнительные. Нажатие Enter при первом запросе выбирает ключ из `keys/default.pub`, при последующих — завершает ввод.

Существующие ключи сохраняются, повторно введённые ключи не дублируются. Для каталога `.ssh` скрипт задаёт права `700`, для `authorized_keys` — `600`.

### 7. SSH‑сервер — `steps/sshd.sh`

Скрипт заменяет `/etc/ssh/sshd_config` конфигурацией из [templates/sshd_config](templates/sshd_config) с выбранным портом. По умолчанию использует `18233`.

- Разрешает вход по публичным ключам.
- Отключает вход root, вход по паролю и клавиатурную интерактивную аутентификацию.
- Отключает X11 forwarding и сохраняет поддержку SFTP.

Перед применением скрипт проверяет конфигурацию через `sshd -t` и сохраняет прежнюю в `/etc/ssh/sshd_config.ocl-backup.*`. Перезапускает SSH с учётом `ssh.socket`; при ошибке применения пытается восстановить прежнюю конфигурацию.

### 8. Межсетевой экран — `steps/ufw.sh`

Скрипт устанавливает UFW, если его нет, и включает его со следующими правилами:

- Входящие соединения по умолчанию запрещены.
- Исходящие соединения по умолчанию разрешены.
- Для действующего TCP‑порта SSH добавляет правило `limit`, ограничивающее частоту подключений.

Существующие правила UFW сохраняются. Порты приложений, например HTTP и HTTPS, нужно открывать отдельно при их развёртывании.

### 9. Оболочка Zsh — `steps/zsh.sh`

Скрипт устанавливает `zsh`, `git` и `fzf`, затем настраивает Oh My Zsh для выбранного пользователя и назначает Zsh его оболочкой по умолчанию.

Использует [templates/zshrc](templates/zshrc) и тему [lenyldes](templates/lenyldes.zsh-theme): двухстрочное приглашение с именем пользователя, сервером, текущим каталогом и состоянием Git.

Подключает подсказки, автодополнение, подсветку синтаксиса, поиск через `fzf`, цветные man‑страницы и плагины для Docker, Docker Compose, kubectl, Helm и Terraform. Сами эти инструменты, кроме `fzf`, данный шаг не устанавливает.

Перед заменой существующих настроек скрипт сохраняет копии с суффиксом `.ocl-backup.*`. Новая оболочка применится после повторного входа.

## Повторный запуск и ошибки

При ошибке установщик останавливается и выводит итог. Уже выполненные шаги сохраняются; общего отката изменений нет.

Повторный запуск снова проходит все шаги. Существующий пользователь и его SSH‑ключи сохраняются, но конфигурации SSH и Zsh снова приводятся к шаблонам проекта. В автоматическом режиме пароль root генерируется заново при каждом запуске.
